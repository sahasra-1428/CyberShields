    Educational Reference Architecture

    How to Identify Fake & Phishing URLs

    Heuristic Engine Guide

    1. Anatomy of a Deceptive URL

    https:// secure.login.sbi.co.in. account-verify-portal .xyz /update-pan
    https:// (Protocol) Encrypts transit only. Does NOT mean safe.
    secure.login.sbi.co.in. (Subdomain) Attacker-controlled text to fool victims.
    account-verify-portal (Real Host) The ACTUAL website server you are visiting.
    .xyz (High-Risk TLD) Cheap disposable domain used for quick spam runs.
    /update-pan (Path) Social engineering hook to harvest credentials.

    2. Critical Security Myths Debunked

    🔒 Myth 1: "The padlock icon (HTTPS) means the site is safe."

    Reality: Over 82% of active phishing websites use HTTPS certificates (via free providers like Let's Encrypt or Cloudflare). HTTPS only encrypts communication between your browser and the scammer's server; it does not verify the owner's legitimacy.

    🌐 Myth 2: "If the website opens normally, it must be genuine."

    Reality: Website availability (HTTP 200 OK) is completely distinct from security. Fraudsters clone official bank or corporate portals with matching layouts, logos, and stylesheets in minutes.

    3. The 7 Heuristic Pillars Inspected by CyberShield

    1. Subdomain Stacking Trick

    Scammers insert trusted names as subdomains (e.g. paypal.com.verify-user.xyz).

    Defense: Read backward from the first single slash to find the true domain.
    2. Typosquatting Swaps

    Swapping look-alike letters/numbers: paypa1.com, arnazon.com, g00gle.com.

    Defense: Inspect character-by-character for substitutions.
    3. Punycode Homoglyphs (xn--)

    Using Cyrillic or Greek letters that look identical to English letters (e.g. Cyrillic 'а').

    Defense: Any URL resolving to xn-- is automatically flagged.
    4. High-Risk Abused TLDs

    Disposable extensions like .xyz, .top, .tk, .work, .icu, .buzz.

    Defense: Financial organizations rarely use cheap, disposable TLDs.
    5. Bare IP Address Hosting

    Hosting portals on direct numeric IPs (e.g. http://192.168.1.1/login).

    Defense: Direct IPs bypass domain WHOIS and domain blocklists.
    6. Obfuscated URL Shorteners

    Hiding real destinations behind bit.ly, tinyurl.com, is.gd, rb.gy.

    Defense: Always preview shortened links with security scanners.
    7. Harvesting Keywords

    Paths packed with triggers: verify-kyc, otp-confirm, update-pan, claim-reward.

    Defense: Banks never ask for OTP or KYC updates via random links.

    4. Four-Step Rapid Field Checklist

    1. Find the true root domain: Trace backward from the first single forward slash /.
    2. Scrutinize every letter: Look for substitution tricks like 1 instead of l, 0 instead of o.
    3. Question the extension: Verify if your bank or provider legitimately uses that specific top-level domain.
    4. Navigate independently: Never click the link in an unsolicited SMS or WhatsApp. Type the official URL manually.
